Project mẫu và cách Claude đọc project

Agent chăm sóc khách hàng cho shop sách “Sách Hay”, gom mọi thứ của 5 domain vào một project thật. Trang này giải thích bằng sơ đồ: cấu trúc thư mục, Claude Code nạp file nào trước, một lượt xử lý đi qua những bước nào, và agent API chạy ra sao.

3. Claude Code nạp gì khi mở phiên

Thứ tự nạp theo tài liệu Claude Code. Settings được gộp trước, sau đó đến bộ nhớ (CLAUDE.md), công cụ (MCP), các mô tả (skills, subagents), cuối cùng là hook SessionStart.

Thứ tự ưu tiên settings (cao → thấp)Thứ tự nạp CLAUDE.md
  1. Managed settings (tổ chức)
  2. Tham số dòng lệnh --settings
  3. .claude/settings.local.json
  4. .claude/settings.json
  5. ~/.claude/settings.json

Rule permission được gộp từ mọi cấp, quy tắc chặt nhất thắng: deny > ask > allow.
  1. Managed policy (tổ chức)
  2. ~/.claude/CLAUDE.md (user)
  3. ./CLAUDE.md hoặc ./.claude/CLAUDE.md (project), kể cả ở các thư mục cha
  4. CLAUDE.local.md (cá nhân, nối sau CLAUDE.md cùng thư mục)
  5. CLAUDE.md ở thư mục con và rule có paths: chỉ nạp khi Claude đọc file ở đó

@duong/dan để import file khác, tối đa 4 tầng.

4. Claude “nhìn thấy” gì trong một request

Context được ghép theo thứ tự cố định. Phần trên ổn định nên được cache, phần dưới thay đổi mỗi lượt.

5. Một lượt xử lý trong Claude Code

Ví dụ: bạn gõ “Sửa lỗi định dạng mã đơn trong tools.py”. Hook PreToolUse chạy trước bước kiểm tra permission.

6. Agent API trong src/agent.py chạy thế nào

Ví dụ: khách hỏi “Đơn SH1024 của tôi đang ở đâu?”.

Diễn biến thật

Hai request cho một câu hỏi

  1. Request 1: system (chỉ dẫn + chính sách, đã cache) + tools + câu hỏi. Claude trả stop_reason: "tool_use" với lookup_order({"order_id": "SH1024"}).
  2. Code của bạn chạy lookup_order, đọc data/orders.json, trả về {"status": "Đang giao", "eta": "2026-10-03", ...}.
  3. Request 2: gửi lại toàn bộ lịch sử + tool_result. Lần này cache_read_input_tokens > 0 vì system không đổi.
  4. Claude trả end_turn: “Đơn SH1024 đang được giao, dự kiến tới ngày 03/10…”.

Nếu khách gõ sai mã “1024”, tool ném ToolError kèm hướng dẫn định dạng → trả is_error: true → Claude tự hỏi lại khách mã đúng.

7. Cùng một tool, hai cách dùng

tools.py là lõi. agent.py gửi schema của nó qua Messages API cho khách hàng. orders_mcp.py mở cùng các hàm đó qua MCP để nhân viên dùng trong Claude Code. Viết một lần, dùng hai nơi.

Tóm tắt & mẹo nhớ

Ghi nhớ cốt lõi

  • Settings do harness áp dụng; CLAUDE.md là kiến thức cho model. Luật cứng đặt trong settings/hook, còn kiến thức và quy ước đặt trong CLAUDE.md.
  • Lúc mở phiên, skill và subagent chỉ nạp mô tả, nội dung đầy đủ chỉ nạp khi dùng. CLAUDE.md ở thư mục con và rule có paths nạp khi cần.
  • PreToolUse chạy trước permission. Exit 2 thì chặn tool và gửi stderr cho Claude.
  • Thứ tự cache: tools → system → messages. Nội dung thay đổi đặt cuối cùng.
  • Code của bạn mới là thứ chạy tool; model chỉ thấy schema và kết quả trả về.

Mẹo nhớ nhanh

  • “S-M-M-S-H” khi mở phiên: Settings → Memory (CLAUDE.md) → MCP → Skills/Subagents (mô tả) → Hook SessionStart.
  • “Chặn trước, hỏi sau”: PreToolUse chặn trước, permission hỏi sau.
  • Settings cao → thấp: “Công ty – Lệnh – Local – Team – Tôi” (managed, --settings, local, project, user).
  • “Deny là sếp”: deny luôn thắng ask và allow, dù rule nằm ở file nào.
  • “Menu trước, món sau”: skill giống menu. Claude đọc tên món (description) trước, gọi món thì bếp mới nấu (nạp SKILL.md).
  • “Tủ lạnh – bàn – đĩa” cho cache: tools là tủ lạnh (ít đổi), system là bàn bếp, messages là đĩa thức ăn (đổi liên tục). Đổi tủ lạnh thì phải dọn lại cả bàn lẫn đĩa.
